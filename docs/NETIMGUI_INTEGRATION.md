# Remote Dear ImGui / NetImgui integration

This branch integrates NetImgui as a transport for Dear ImGui draw data generated by a headless simulator and rendered by Reg's existing Vulkan backend.

The target architecture is intentionally split into three layers:

1. **NetImgui transport/core** — TCP, packet decoding, remote-client lifecycle, texture synchronization, and input forwarding.
2. **Reg adapter** — isolates NetImgui private/server APIs from the rest of Reg.
3. **Reg renderer** — owns SDL3, Vulkan, swapchain, command buffers, and presentation.

NetImgui must not own a window, graphics device, swapchain, or presentation path in Reg.

The first integration milestone is a minimal vertical slice: receive one remote Dear ImGui frame, reconstruct `ImDrawData`, synchronize the font texture, render it through `imgui_impl_vulkan`, and return SDL3 mouse/keyboard input to the remote client.

## Dependency policy

NetImgui is pinned to a known upstream commit. All direct use of NetImgui internal/server types must stay behind `src/remote/NetImguiHost.*` (or an equivalent adapter) so that upstream changes do not leak through Reg.

If upstream changes are required, move the pinned dependency to a project fork while preserving the same adapter boundary. Avoid changing the NetImgui wire protocol unless there is no viable alternative.

## Dear ImGui versioning

Reg currently uses its own pinned Dear ImGui submodule. NetImgui must compile against that same Dear ImGui source tree; it must not introduce a second Dear ImGui build into the executable. Compatibility with the currently pinned WIP Dear ImGui revision must be verified before enabling the transport in production builds.
